# Scientific rationale for the per-block SO-PLS check

## Why this check is justified

The frozen SO-PLS fitting implementation accepts a scalar requested component count and applies it to every included block. The earlier benchmark therefore evaluates a declared uniform-component SO-PLS family. A model with unequal block complexities, such as (2,1) or (1,3,2), is absent from that family. The maintainer documentation for the multiblock package explicitly supports components per block and sequential as well as global component optimization. A bounded per-block follow-up is consequently a relevant structural sensitivity analysis.

The earlier result is not invalidated merely because its candidate class is restricted. The new condition supplies an additional declared model class; it preserves the old fitting source, original component bank and all archived predictions. The extension must be reported regardless of direction. Retaining historical results does not require a new result to agree with them; if the new result qualifies the interpretation, that qualification must also be retained.

## What the existing boundary records establish

A read-only audit of all fifteen historical benchmark tasks found 165 target-by-outer-task choices for U+R and 165 for U+R+N. Both masks selected requested k=10 in 52/165 choices, or 31.515%. The suggested triple count of 51/165 does not match those task payloads. The V8 unscaled condition gives the same counts.

All selected U+R fits with requested k=10 have 20 active components in total. All corresponding triple fits have 30 active components. No selected fit was reduced by the rank cap. The complete active-component ranges are 2--20 and 3--30, respectively.

These findings establish frequent selection of the upper searched value. They do not establish that the algebraic rank constraint is reached, or that larger component counts would improve prediction. Approximately 111--112 independent training bottles and 20 or 30 extracted directions describe model size relative to the training sample; the direction count is not a formal effective-degrees-of-freedom estimate. PLS directions depend on the response, so model complexity cannot be reduced to counting the extracted directions alone.

## Scope of the declared new grid

The new per-block candidates are exactly 1, 2, 3 and 5. Their maximum total requested components are therefore 10 for U+R and 15 for U+R+N. The historical uniform bank includes k=10, with totals up to 20 and 30.

Consequently, the new comparison changes block-wise allocation and the maximum allowed complexity together. It is a structural and complexity sensitivity. It does not isolate equal versus unequal allocation at a matched maximum, and does not test whether increasing the old upper value would help. A matched uniform grid capped at five is not added in this release: the extension remains the single requested condition with fifteen outer tasks. Do not interpret an improvement, deterioration or null result as a pure causal effect of allowing unequal block counts.

The per-block grid also requires at least one requested component for each included block. It does not include a zero-component NIR option and does not select the acquisition mask. The separate V8 shared-weight experiment addresses zero NIR contribution. A degenerate fitted block can have zero active components under the preserved numerical rules; requested counts and active counts are reported separately.

## Training-only sequential selection

For each target, declared block order and original preprocessing path, the sequential rule compares the four values for the next block using the existing inner threefold bottle partitions. Earlier selected counts are fixed while comparing that stage. Every candidate prefix is fitted on the current inner fitting rows and evaluated on that fold's validation rows.

The residual used to fit a later block must be generated by a prefix fitted on the current inner fitting rows. Its validation counterpart uses that same prefix's held-out prediction. It is not acceptable to fit a prefix on all outer-training bottles, compute residuals once and then cross-validate the later block: that would allow inner validation responses into the prefix fit.

Scoring uses cumulative predictions against the original validation concentrations, with pooled raw-unit squared error for each target. The final stage score selects the order and preprocessing path under the frozen deterministic tie rule. These are adaptive inner selection scores; reusing the folds across greedy stages does not make them unbiased performance estimates. The untouched outer predictions remain the assessment of predictive error.

The scalar and vector fitting entry points must preserve response centering and scaling, predictor centering and scaling, sequential score orthogonalization, least-squares tolerance, component rank caps, PLS solver settings, residual updates and prediction accumulation. A scalar k and a vector with the same k repeated for each block must agree in synthetic parity tests. The new extension receives no outer evaluation labels for tuning or fitting, and task failure must stop the run rather than select a fallback using outer errors.

## Computational cost

The original preprocessing choices and all orders imply six order/treatment paths for U+R and 54 for U+R+N. With four component values, three inner folds and two or three sequential stages, nine block fits per target is not an adequate count for this design.

Naively evaluating every complete prefix requires about 4,104 block fits per target and outer task, before selected final fits. Memoizing identical complete prefixes across paths can lower the combinatorial count to approximately 2,748, compared with approximately 2,610 in the old uniform full candidate bank. An incremental fitted-state cache could lower it further, but it adds implementation complexity. These counts depend on the caching design and are not measured runtimes. Record actual evaluation counts and durations; do not promise an unmeasured completion time.

## Evidence and interpretation

The new condition preserves all eleven targets and the existing paired U+R versus U+R+N definition. The final reports retain component vectors, block order, requested and active counts, inner stage scores, outer task losses, pooled panel effects and paired conditional bottle-bootstrap intervals. Shared bottle draws preserve repeated visits and all eleven targets together.

The new method must appear in the declared expanded multiplicity family alongside the historical methods. New adjusted values are written to new tables; historical table values remain inspectable. Fixed-prediction conditional intervals and approximate corrected repeated-CV sensitivity are distinct statistical summaries. Neither supplies independent-batch validation or a complete retraining-procedure uncertainty interval.

The follow-up is prespecified relative to its own unobserved outcomes, after the V8 cohort results have already been examined. It is therefore a frozen retrospective structural follow-up, not a prospective validation on a new cohort. The result must remain public whether it strengthens, weakens or qualifies the earlier no-stable-panel-gain finding.

## Primary sources

- Maintainer reference, Sequential and Orthogonalized PLS: https://khliland.github.io/multiblock/reference/sopls.html . Documents per-block component vectors and sequential/global optimization.
- Official CRAN reference, multiblock SO-PLS: https://search.r-project.org/CRAN/refmans/multiblock/html/sopls.html . Documents the same interfaces; its scalar ncomp represents an overall maximum, which is distinct from repeating a scalar independently for every block in the frozen implementation.
- Kraemer and Sugiyama, The Degrees of Freedom of Partial Least Squares Regression: https://arxiv.org/abs/1002.4112 . Establishes that response-dependent PLS direction selection makes latent-component count an inadequate effective-degrees-of-freedom estimate.
